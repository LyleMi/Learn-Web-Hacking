Attack type
========================================

Gold note utilization
----------------------------------------
During the authentication process, the TGT will be obtained through the communication between the client and the AS. The golden ticket is the forged ticket granting ticket (TGT), also known as the authentication ticket.

Golden ticket utilization requires communication with the DC and obtaining the hash of krbtgt, but it can obtain any Kerbose service permissions.

Silver Bill Utilization
----------------------------------------
Silver Tickets forgery uses the third step in Kerberos authentication. In the third step, the client will request a certain service on the server with the ticket. If the verification is passed, it can access the specified service on the server. The ticket here is based on client info, server session key, end time, and server hash. Here the client info is known, the end time can be constructed, and the server session key is generated by TGS, so only the NTLM hash of the server is enough. The counterfeit banknote is TGS and can only access designated services.

DCSync attack
----------------------------------------
When there are multiple domain control servers in the domain, in order to synchronize the modifications of the domain control servers, Microsoft provides a synchronization mechanism based on the Remote Directory Protocol `DRSR <https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-drsr/f977faaa-673e-4f66-b9bf-48c640241d47>`_.

Between multiple domain control servers, domain data is synchronized every once in a while. The domain control server that needs to be synchronized sends a GetNCChanges request to other servers, and the request contains the data that needs to be synchronized. When the amount of data is large, this process is repeated.

DCSync is a technology that uses this mechanism for domain penetration. It was co-written by Benjamin DELPY gentilkiwi and Vincent LE TOUX. It was a function added to mimikatz in 2015 that can export the hashes of all users in the domain.

This method requires any of the following permissions:

- Users in the Administrators group
- Users in the Domain Admins group
- Users in the Enterprise Admins group
- Computer account for domain controller

Or have specific DACLs:

- DS-Replication-Get-Changes
- DS-Replication-Get-Changes-All
- DS-Replication-Get-Changes-In-Filtered-Set

When there is no administrator user, but with WriteDACL permission, DCSync can be done by writing to the above DACL.

For this kind of attack, you can detect the initiator of GetNCChanges. If the corresponding request is initiated by a non-domain control machine, it can be considered a DCSync attack.

DCShadow attack
----------------------------------------
DCShadow was proposed by Benjamin Delpy and Vincent Le Toux, security researchers from France, at the 2018 Microsoft Blue Hat (Blue Hat) conference.

The DCShadow attack involves creating a malicious domain controller in an Active Directory environment and using it to push malicious objects.

pass the hash attack
----------------------------------------
Pass-the-Hash (PTH) is an attack method that authenticates by passing NTLM hashes. Commonly used tools include mimikatz and so on.

ticket passing attack
----------------------------------------
Pass-the-Ticket Attacks (PtT) are a method that uses Kerberos tickets instead of plaintext passwords or NTLM hashes. Probably the most common use of PtT is with gold notes and silver notes. Accessing a host via PtT is fairly simple.

Kerberoasting Attacks
----------------------------------------
The Kerberoasting attack was `disclosed <https://www.youtube.com/watch?v=PUyhlN-E5MU>`_ by Tim Medin at the 2014 DerbyCon conference. It means that any host in the domain can query the SPN. Kerberoasting requests TGS from all services in the domain and then performs brute force cracking.

Roasting AS-REP
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
The attack enumerates accounts in the domain that do not require Kerberos pre-authentication, requests an encrypted message from these accounts, and attempts to obtain the account hash offline. This method requires the account to explicitly set ``DONT_REQ_PREAUTH``.

Kerberos Delegation Attacks
----------------------------------------
In a domain, A uses Kerberos authentication to access service B, and B uses A's identity to access service C. This process can be understood as delegation. Delegation is mainly divided into two types: unconstrained delegation and constrained delegation. Unconstrained delegation can access any other services in the domain, while constrained delegation restricts authentication and cannot access other services.

Kerberos Delegation (Kerberos delegation) attacks are divided into unconstrained delegation attacks and constrained delegation attacks. The principle is based on the fact that delegated accounts have been configured in the domain to obtain the permissions of other accounts.
